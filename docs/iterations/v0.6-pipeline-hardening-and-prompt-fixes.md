### Session 2 — 2026-03-25: Strategy, Instruction System Overhaul & ROADMAP

No pipeline code changed this session. Work focused on responsible AI strategy, documentation architecture, and strengthening the agent instruction system.

**Accuracy & trustworthiness strategy defined:**
- Mapped a three-layer accuracy build: pipeline reliability (v0.6) → analysis correctness (post-v0.6) → trust as a relationship (longer term)
- Identified that current work covers responsible *output framing* but not yet responsible *input validation* (research adequacy)
- Trustworthiness strategy: limitation disclosure in every report, reasoning visibility per gap, version each report, user-facing changelog, expert review loop (deferred)

**Agent instruction system restructured (`CLAUDE.md`):**
- Behavior rules moved to the top of the file — they now load before any project context
- Rules 1–3 expanded to full detail with BAD/GOOD examples (previously condensed summaries)
- Rule 2 (present before acting) strengthened with anti-rationalization language: named the specific failure mode where agents classify directional instructions as "unambiguous" to skip the present-first step
- Rule 4 expanded with "every user-facing string is a branding opportunity" framing
- `docs/ROADMAP.md` added to the reading list and after-session checklist
- Pre-commit checklist updated: added "report as table" instruction, updated `.gitignore` check to reflect current protected files
- Version updated from v0.5.1 → v0.6

**`.cursor/rules/` retired from git:**
- Decision: merge all rule content into `CLAUDE.md` (Option C) so rules are always in context, not dependent on agents choosing to read separate files
- `.cursor/rules/` files kept locally for Cursor compatibility but removed from git tracking
- `.gitignore` updated: `!.cursor/rules/` exception removed, `.cursor/` now fully ignored
- User ran `git rm --cached` on the three rule files

**`docs/ROADMAP.md` created (local only, not in git):**
- Four-pillar structure: Pipeline Reliability, Accuracy, Trustworthiness, Product Direction
- Status-based (not version-locked): items move between pending/in-progress/planned/deferred without version reassignment

**`memory/MEMORY.md` updated:**

- Documentation workflow updated to include ROADMAP.md step
- New feedback memory created: `feedback_present_before_acting.md` — captures the Rule 2 anti-rationalization failure mode for future sessions

**Agent behavior insight documented:**
- Identified that rule exceptions create rationalization surfaces — agents search for a reason the exception applies rather than asking whether it genuinely does
- Root cause: optimization pressure toward action, exception as "door with a key to find"
- Fix: name the failure mode explicitly inside the rule, flip burden of proof, use specificity not abstract "judgment" as the qualifier

### Session 3 — 2026-07-26: HIGH + MEDIUM Pipeline Fixes Implemented

Implemented the trustworthiness-focused fix set. All changes verified to compile
(`python -m py_compile agent.py prompts.py streamlit_app.py`); functional test runs pending.

**Root refactor — `conduct_research()` returns structured data:**
- Changed return type from a flat string to a dict: `findings_text`, `sources` (each with
  `title`/`url`/`query`), `successful_queries`, `failed_queries`, `num_results`. This single
  change is the foundation for #29 (detect empty), #14 (show sources), and #7 (measure adequacy).

**#29 — silent research-failure surfacing (DONE):**
- Added `EmptyResearchError`. `run_analysis()` aborts with an error dict when `num_results == 0`
  (no fabricated report); `_run_pipeline()` raises `EmptyResearchError`, caught with a calm
  user-facing retry message. Thin-but-nonzero research sets a `research_limited` flag that adds
  an honest limitations note to the report and a warning banner in the UI.

**#9 — misleading system prompt (DONE):**
- Removed the false "You have access to web search tools" claim. `SYSTEM_PROMPT` now accurately
  states the agent supplies findings, Claude does not search, and Claude should flag thin
  findings rather than invent specifics (also reinforces anti-hallucination).

**#7 — research adequacy loop (DONE, lightweight):**
- Added `gather_research()` + `MIN_ADEQUATE_RESULTS`, `_broadened_queries()`, `_merge_research()`.
  If the first research pass is thin (< 4 results), one broadened supplementary search round runs
  and merges (dedup by URL). Heuristic, not an LLM-driven loop — full agentic loop deferred to v0.7.

**#31 — user feedback button (DONE):**
- 👍/👎 feedback under each report, stored in the existing `user_events` table
  (`event_type="feedback"`, `event_data={"rating": ...}`) — no schema migration. Session flag
  prevents double-submission.

**#14 — sources in saved report (DONE):**
- `save_report()` adds a "## Sources" section (markdown links); the UI adds a "🔗 Sources" tab.

**Deferred as planned:** #30 (quality heuristics), #13 (research preprocessing), and all LOW
items (#8, #23, #24, #25, #32) — documented as known & deferred, not chased.
