### Session 4 — 2026-08-07: Currency, Fine Print, Delivery Tooling — and the First Accuracy Test

**Current-date injection.** The search planner had no sense of "now", so it anchored queries to
its training-era year — producing searches ending in "…2024" for a report generated in August
2026, and missing a regulatory deadline that had shifted by 16 months. Fixed by adding
`{current_date}` to **both** prompts: the planner (so it searches the right year) and the
analysis (so it can judge whether a deadline has passed or been superseded). The analysis prompt
gained a `DATES & CURRENCY` section instructing it to check every date against today, prefer
newer dates when the research shows one moved, and stay vague rather than assert a date it cannot
support. `_today()` in `agent.py` resolves per call rather than at import, so a long-running
Streamlit process cannot get stuck on the date it started.

**Report disclaimer.** New `REPORT_DISCLAIMER` in `prompts.py`, defined once and attached to the
saved markdown, the on-screen report, the download and the database copy. It also had to be
re-attached in `streamlit_app.py`'s save-failure fallback, which previously emitted a report with
no fine print — a guarantee that leaked only on an error path.

**Custom-run CLI.** `agent.py` gained `argparse` flags (`--use-case`, `--technology`,
`--industry`) so a one-off analysis can run without adding real inputs to a file in a public repo.

**`export_pdf.py`.** New module rendering a saved report as print-ready HTML for Save-as-PDF.
Deliberately dependency-free — the browser is already the best PDF renderer available, and PDF
libraries are a poor install risk on Windows. `--client-ready` drops the internal search-queries
section; sources always remain.

## Test Results

**First end-to-end accuracy test — 2026-08-07. Result: FAILED.**

Two runs on identical input, nine minutes apart, with every substantive claim checked against
primary sources.

| Check | Result |
|---|---|
| Date defect fixed | ✅ Queries moved from `…2024` to `…2026` / `…latest`; the analysis reasons about time correctly |
| Regulations cited to the correct article/section | ❌ |
| Every date current, not superseded | ❌ |
| Every quoted phrase traceable to the right body | ❌ |
| Nothing material missing for the scenario | ❌ |
| Stable across runs | ❌ |

**The central finding — the fix worked and the output got worse.** Before the fix, the report
named a compliance deadline vaguely and hedged. After it, the model knew today's date, compared
it against a stale fact from the research, and declared the deadline "has now passed — urgent
attention." That deadline had in fact been deferred by 16 months two months earlier. The failure
changed shape from *vague and stale* to *specific, urgent and wrong* — which for a compliance
tool is a move in the wrong direction, because it sounds more trustworthy.

> **Making a system more capable makes its remaining flaws more convincing.** Better reasoning
> over bad input does not produce a better answer; it produces a more persuasive wrong one.

**Attribution errors recurred** despite the v0.6 honest-prompt fix: a commentary blog was quoted
as though it were a professional body's own standard, and third-party SEO sites were cited for a
vendor's own published terms. **Every factual error traced to a low-quality source.**

**Drift was severe.** The two runs produced different top-priority findings and different
regulation sets; one included the governing professional standard for the scenario's industry and
the other omitted it entirely. Which risks a user is told about depended on chance.

**Conclusion:** the date was a symptom. Source quality is the cause — research surfaces
commentary above primary sources, and nothing in the pipeline guarantees coverage or corroborates
a claim. The version stays untagged until the research layer meets that bar.
